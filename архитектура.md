# Ферма — техническое предложение 0.1

Дата: 2026-11-22. Автор: роль fullstack разработчика. TASK-036. Статус: на согласовании; исходники не созданы, стек не утверждён.

## Рекомендуемая основа

Одиночная HTML/CSS/JavaScript игра без фреймворков, установки зависимостей и backend. Предлагаемый путь исходников: Ферма/. После одобрения — index.html, styles.css и отдельные JS-модули каталога, правил, состояния, сохранения и интерфейса. Локальный HTTP-просмотр предпочтителен для ES modules; команду запуска выбрать по уже доступным инструментам, без установки. Открытие file:// не обещается. Серверный режим потребует отдельного решения, а не простой замены адреса сохранения.

## Разделение ответственности

- Каталог: устойчивые ID культур/животных, цены, длительность, продукция, условия открытия. Числа из брифа собраны здесь.
- Модель: единственный источник состояния — версия схемы, монеты, склад, грядки, животные и прогресс подсказок. Модель не обращается к DOM и localStorage.
- Команды: посадить, собрать, покормить, забрать, купить и продать. Команда проверяет ресурсы и состояние, затем атомарно возвращает новое состояние или понятную ошибку; UI не начисляет деньги самостоятельно.
- Сохранение: адаптер load/save с проверкой формы, конечности чисел, неотрицательных остатков, допустимых ID и ограничений количества объектов. Схема имеет schemaVersion; миграция выполняется в памяти и сохраняется лишь после успешной валидации. Будущая версия не сбрасывается в начальную.
- Интерфейс: DOM-кнопки и адаптивная сетка; SVG только для оформления. Отображение готовности не выполняет начислений.

## Время и сохранение

Предложение: хранить readyAt; по возвращении вкладки пересчитать готовность. За отсутствие созревает только уже посаженное/накормленное, продукция выдаётся вручную один раз. Нет бесконечного автоматического заработка. Смена часов может ускорить локальную игру — допустимое ограничение одиночного прототипа, непригодное для соревнования и платежей.

localStorage с отдельным ключом farm.save.v1; сохранение после успешной команды. Ошибку квоты/запрета показать; продолжать в памяти с предупреждением об утрате после закрытия. Повреждённые или неизвестные сохранения не затирать, предложить явное начало новой игры. Две вкладки: событие storage и проверка ревизии до команды, при конфликте приостановить действия и предложить загрузить актуальное состояние. Это не гарантирует транзакции между вкладками; полноценную параллельную игру пока исключить из предлагаемого режима.

Для будущего обновления подготовить экспорт/импорт сохранения как локального файла с валидацией; включать в первую реализацию только после согласования объёма. Полный офлайн запуск/PWA отдельно: локальное сохранение не означает офлайн доступность страницы.

## Проверки реализации

Чистое ядро проверить доступным Node.js без сторонних пакетов: сквозной цикл, точная граница таймера, двойной сбор, нехватка ресурсов, бесконечные/отрицательные значения при загрузке, страховка тупика, загрузка старой/будущей схемы и отказ хранилища. Временные значения передавать в модель явно, чтобы тесты не ждали реального роста.

После этого — браузерные сценарии и визуальный просмотр по дизайну, перезагрузка, возврат из фоновой вкладки, конфликт двух вкладок и отсутствие внешних запросов. Зафиксировать реальные результаты, браузер и размеры. Тесты приложения пока не запускались, приложения нет.

## Путь развития

Новые культуры/животные добавляются в каталог, новая механика — отдельной командой и состоянием с миграцией. Не строить универсальный движок до появления потребности. При аккаунтах понадобится авторитетная серверная модель с проверкой команд, серверным временем, аутентификацией и контролем повторов; клиентские сохранения нельзя считать доверенным балансом. Хостинг, БД и API выбираются отдельно с учётом нагрузки и бюджета. Подключения, миграции, публикация и отправка данных отдельно подтверждаются.
